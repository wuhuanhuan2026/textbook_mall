## 三、主选题风险与删减方案

### T1 教材商城系统

**最大风险：**
1. 微服务架构（Spring Cloud + Nacos + Gateway）学习曲线陡峭
2. 涉及 11 个模块，代码量较大
3. 需要管理多服务端口和依赖关系

**删减方案：**
- 保留核心业务：教材管理、购物车、订单、用户管理
- 简化非核心：支付仅保留余额支付，不做真实支付对接
- 不做：短信通知、评价审核、收藏功能

### T2 校园活动报名系统

**最大风险：**
1. 并发报名场景需要处理名额竞争
2. 需要处理活动状态机（草稿/发布/截止/取消）

**删减方案：**
- 保留：活动发布、浏览、报名、审核
- 简化：不做支付、不做短信通知

## 四、最终选题决策

**主选题：T1 教材商城系统**

**选择理由：**
1. 数据可自行构造，不依赖外部授权
2. 业务闭环清晰：管理员发布 → 学生浏览 → 购买 → 查看订单
3. 能覆盖完整的软件开发流程（需求、设计、开发、测试、交付）
4. 已具备前后端工程骨架和 11 个微服务模块
