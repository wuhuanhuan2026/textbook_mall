核心场景：


场景1：学生购买教材

参与角色： 学生

前置条件： 已登录，教材已上架且有库存，余额充足

主流程： 浏览教材→查看详情→加入购物车→去结算→选择地址→提交订单→支付

异常流程： 库存不足、余额不足、地址未填写、重复提交

完成状态： 生成订单记录，库存扣减，余额扣减



场景2：管理员发布教材

参与角色： 管理员

前置条件： 已登录，具有管理员权限

主流程： 登录→进入管理后台→教材管理→新增教材→填写信息→保存草稿→上架

异常流程： 信息不完整、价格非法、库存负数

完成状态： 教材状态变为 PUBLISHED，学生端可见



场景3：游客浏览教材

参与角色： 游客

前置条件： 无需登录

主流程： 打开首页→浏览教材列表→按分类筛选→搜索关键词→查看详情

异常流程： 无匹配结果、网络失败

完成状态： 展示教材信息


预期结果与人工检查：

每个故事能明确识别角色、目标和价值。

学生购买故事包含登录、浏览、加入购物车和下单。

管理员故事包含发布教材和查看订单。



实际结果：

✅ 9 个用户故事已编写。

✅ 3 个核心场景已详细描述。


常见错误与定位方法：

把技术实现写进用户故事会限制方案，应移到设计阶段。

故事没有结果时无法验收，应补充可观察状态。
